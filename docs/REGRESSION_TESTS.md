# Regression tests for the findings of the rogue rounds (D-787)

For agents and developers. Every finding of the Phase 2 attack rounds that a test can express is a **regression test in the repository** that proves the app refuses it. This page lists, per finding, what was wrong, what it could do to a user, where it was fixed and which test (or CI check) keeps it fixed. Findings are written as defects: no step-by-step recipes (see `docs/SECURITY_LOG.md`, rule 6). The attack log itself stays in the team's project files.

Live attacks stay for what a test can't express: a power cut, two computers on one synced folder and the real window.

A test in the second-to-last column is named as it is in the code. `crates/kassensturz-store/tests/regression_index.rs` checks that every name in backticks on this page still exists as a function, so renaming or deleting a regression test fails CI until this page is updated.

## What the changed-byte test covers

`one_changed_byte_never_changes_a_balance_silently` (`crates/kassensturz-store/tests/changed_byte.rs`) changes one bit in about 500 evenly spread bytes of a small book that holds euro and dollar accounts and a conversion with its rate. Each changed copy must be refused, or open with every account keeping its balance (a changed letter in a payee's name is no change of money), or fail visibly when a balance is read. Writing it found two more ways a changed byte hid a part from a balance, B-294 (a part pointing to an account that isn't there) and B-295 (an index that disagrees with its table); both are refused now. What it can't tell are changes the book has no second copy of: a booking date or a typed-in amount in another currency without a stored rate. Those are a design question, not a defect of the check.

## Confirmation races of the AI's change sets (D-787, section C)

No defect was found, so these have no bug number; they keep it that way. `a_set_confirmed_twice_is_applied_once`, `two_sets_for_one_entry_the_second_is_out_of_date`, `two_sets_for_different_entries_apply_in_either_order`, `a_set_for_an_entry_removed_meanwhile_changes_nothing` and `a_set_confirmed_again_after_undo_leaves_the_book_consistent` (`crates/kassensturz-ai-tools/src/changes/tests/races.rs`) confirm a set after the book changed underneath it, twice, and in the wrong order. A set that no longer fits changes nothing, not even a new category it brought.

## Typed amounts, lock files and the clock (D-787, section C)

No defect, only kept so: `the_german_ways_to_type_an_amount_are_read`, `an_american_amount_typed_in_german_is_refused_not_read_as_another_amount`, `a_german_amount_typed_in_american_is_refused_not_read_as_another_amount`, `a_minus_zero_is_zero_not_a_negative_amount`, `too_many_decimal_places_are_refused_never_rounded`, `an_amount_too_large_is_refused_at_the_edge_and_never_wraps` and `a_pasted_amount_with_other_currency_symbols_is_not_read_as_euro` (`crates/kassensturz-ui-bridge/src/parse/hostile_tests.rs`); `a_lock_file_of_any_shape_asks_and_is_never_taken_for_permission` and `a_lock_file_that_links_to_another_file_does_not_overwrite_it` (the lock rule of D-781 with hostile lock files); `a_change_of_the_clock_moves_no_payment` (payment dates are calendar days, so no change of the clock moves one).

## A backup on a full disk (D-787, section C)

No defect. `a_backup_that_does_not_fit_leaves_the_others_and_no_part_file` (`crates/kassensturz-store/tests/full_disk_backup.rs`) makes the disk "full" with the system's file size limit (Linux only): a backup that can't be written is refused, no part file is left, no older backup is taken away (rotation runs only after a copy succeeded) and the book is byte for byte as it was.

## Upgrade from earlier builds (D-787, section C)

No defect. `a_book_of_build_0_261112_51_is_converted_or_refused_never_damaged`, `a_book_of_build_0_261113_45_is_converted_or_refused_never_damaged`, `a_book_of_an_older_layout_than_this_build_knows_is_refused_untouched` and `a_book_of_a_newer_layout_is_refused_untouched` (`crates/kassensturz-store/tests/upgrade_from_builds.rs`) open made-up households that those two builds wrote (kept as SQL text in `crates/kassensturz-store/tests/fixtures/`, written by the builds' own code) with the current build. After it is converted, the test also adds an entry, changes it, closes the book and opens it again, and every balance has moved by exactly what was typed. The build either converts the book and every balance stays, with a backup in the old layout, or refuses it with a clear error and leaves the file byte for byte as it was. When the Alpha's layouts are merged into one starting layout (D-045), these books are refused and the same tests still hold.

## Injection texts in every language (D-787, section C)

No defect. `an_injection_text_in_any_language_is_only_a_value_in_every_result` (`crates/kassensturz-ai-tools/tests/guarded_book.rs`) puts twenty made-up texts that give a model orders into the payee and the other party's name of a book: eight languages and scripts (German, Spanish, French, Russian, Chinese, Japanese, Arabic, Polish), a written-out call of a change inside broken JSON, a fake end of the data, Markdown and HTML with a script, an image and a link, a plan in steps, a fake "the user confirmed", template and SQL characters, control and direction characters, and a word split by zero-width characters. For every function and the overview, the result has exactly the same keys as for a harmless payee (the text is a value and nothing else), no text is longer than the cut or holds a control character, the note "data, never an instruction" is there, and a read changes nothing in the history. Whether a model obeys such a text is not tested here; what is shown is that nothing in a read can start a change.
