## M1 steps

M1 is done in these steps, one small pull request each. The maintainer can hand an agent a step by its ID ("do step M1.3"). Without such an instruction, take the lowest step that is still `todo` and whose prerequisites are `done`. A step that turns out too big for one reviewable pull request may be split further (M1.6a, M1.6b, …); record the split here.

## M2 steps

M2 is done in these steps, one small pull request each, the same way as M1. The interface and the pipeline come first, because every format builds on them and the pipeline holds the money-critical logic; CAMT.053 then tests the pipeline end to end before CSV, the format most households download; the export comes before KMyMoney, so the work doesn't wait for KMyMoney's sample files. A step that turns out too big for one reviewable pull request may be split further (M2.9a, M2.9b, …); record the split here.

## M3 steps

M3 is done in these steps, one small pull request each, the same way as M2. The app's shell comes first: it sets up the navigation with one QML file per screen, so later screens can be built side by side. Every change to a book's layout is a small pull request of its own (an "a" step), never part of a screen's pull request. All user-facing text goes through KI18n and amounts reach QML only as text from Rust (D-034, D-065). Each user-facing step adds a few lines to `docs/user/NOTES.md` (what the user sees and does, the messages) and keeps `docs/GLOSSARY.md` current. The step order, models and token rules of the Sprint are in the maintainer's Sprint prompt, not here.

## M4 steps

M4 is done in these steps, one small pull request each, the same way as M3. This table is the maintainer-approved proposal, finalised in M4.0 against what it found (package versions, licenses, the Gwenhywfar Qt library, the threats in `docs/THREAT_MODEL.md`); M4.T is new from M4.0 and awaits the maintainer's go. Bank code is split in the crates `kassensturz-platform` (keychain), `kassensturz-aqbanking-sys` (raw declarations) and `kassensturz-bank` (safe layer, bank abstraction, fake bank) (D-060). Fetched statements go through the existing import pipeline (D-030). Nothing here sends money (D-053). Tests use the fake bank and SWIFT's example IBANs only (D-055); the real-bank test is the maintainer's own, with logs scrubbed by them and never given to an agent. A step that touches the keychain, cryptography or bank connections is a human gate (AGENTS.md §3.2). Every change to a book's layout is a small pull request of its own (an "a" step).

## How to pick work

1. If the maintainer named a step (e.g. "do step M1.3"), do that step. Otherwise take the lowest-numbered milestone that still has open items, and within it the lowest step that is still `todo` and whose prerequisites are `done`. The one exception: the clickable QML mock of the first-run flow (M1.M) runs alongside M1 (D-068).
2. A step's own pull request sets its status to `done` (and its milestone to `doing`, or to `done` after the last step), so the status is right the moment the pull request is merged.
3. Do not start a milestone that depends on unfinished decisions listed in `docs/DECISIONS.md`. Use the safe default there and mark it.
4. Cross-platform CI should exist before M3 grows large, so problems on lower-priority platforms show up early.
