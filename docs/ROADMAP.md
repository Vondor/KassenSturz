## User Sprints

After M7a the work runs in User Sprints: a round with testers whose work comes from what they find (collect, build, prototype rounds, retro). Release stage: Alpha until the maintainer gave the stage Go to Beta on 17 Nov 2026, after US7 (D-824); Beta since then, so every change to the book or settings format is a migration with an automatic backup and a test. One table row per item, one table per Sprint, like the milestone steps above (D-708). Columns as in the milestone steps: the item's number from the sorting list, scope (build thread, decision numbers, what is changed and why), needs, tier and effort, **status**. A **later** item says what it waits for; a **not done** line says why it was dropped. Issues of later items stay open with the label `later`.

User Sprints 1 to 7 are in [`history/ROADMAP_DONE.md`](history/ROADMAP_DONE.md) (D-962); the newest Sprint below is the current work.

## How to pick work

1. If the maintainer or the coordinator named a step, do that step. Otherwise take, in the current Sprint (the last block under "User Sprints"), the lowest step that is still `todo` and whose prerequisites are `done`. Between two Sprints (Nirvana, D-949) there is no step list: the work comes from the coordinator.
2. A step's own pull request sets its status to `done` (and its milestone to `doing`, or to `done` after the last step), so the status is right the moment the pull request is merged.
3. Do not start a milestone that depends on unfinished decisions listed in `docs/DECISIONS.md`. Use the safe default there and mark it.
